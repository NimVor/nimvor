# WhaCP 1.0.0-rc1 — release-readiness audit

This is the working audit for taking WhaCP from the unreleased 0.5.0 to
1.0.0-rc1. It records what exists, how it is tested, what was found and
what was fixed. It is updated as work lands. "Tested" means an automated
test in this repository that runs in CI, unless stated otherwise.

Severity scale: **BLOCKER** (server compromise, cross-tenant data,
authorization bypass, privileged command execution, config/data loss,
unreliable restore, broken upgrade or installer), **CRITICAL**, **HIGH**,
**MEDIUM**, **LOW**, **INFO**.

## 3. Findings

| ID | Severity | Area | Finding | Status |
|---|---|---|---|---|
| F-01 | **BLOCKER** | Tenant isolation | Customers and resellers could open `/domains`, `/php`, `/ssl` and `/cron`, which showed the whole server inventory: other tenants' domains, document roots, certificates and PHP pools, and system cron commands (which can contain credentials). | **Fixed** (82cd9db): inventory filtered to the user's own websites; system cron, accounts, services and schemas hidden. Regression test added. |
| F-02 | HIGH | RHEL | The commands added for RHEL (`dnf`, `rpm`, `firewall-cmd`, SELinux tools) were missing from the agent's allowlist (a reformatting broke an edit), so on RHEL packages could not be installed, firewalld was not seen and SELinux labels were never applied. | **Fixed** (f7b8b85) + test |
| F-03 | HIGH | RHEL / SELinux | Atomic writes replaced files with ones carrying the folder's default label (e.g. `/etc/named.conf` → `etc_t`), breaking BIND. | **Fixed** (f7b8b85): the label is carried over |
| F-04 | MEDIUM | Webmail | Roundcube's pool locked `include_path`; Roundcube refuses to run. Found by the real-host test. | **Fixed** |
| F-05 | LOW | Git deploy | A captured valid webhook request can be replayed to re-trigger a deployment of the configured branch (no delivery-ID de-duplication). Impact limited to redeploying the same branch. | Accepted for rc1, documented |
| F-06 | MEDIUM | Redis | ACL users could not be created on Redis 6.2 (`&pattern` after `allchannels`). | **Fixed** (f7b8b85) |
| F-07 | HIGH | Installer | The installer is not exercised on Ubuntu in CI (only on the AlmaLinux VM). | **Fixed**: CI now runs `install.sh --enable-writes` on the Ubuntu runner and in the AlmaLinux VM, followed by `tests/integration/postinstall.sh` (sign in over HTTP, create a PHP website and check it is served, create a database, install a certificate and check HTTPS, back up, damage the file and the database, restore, verify, delete). Passed locally against a real install. |
| F-08 | INFO | Plugins | Plugins are PHP code loaded into the panel process with the panel's rights (including the agent token). Only administrators with `plugins.manage` install them. Trust model must be documented. | **Documented** (`docs/plugins/README.md`, `SECURITY.md`) |
| F-09 | HIGH | RHEL | AlmaLinux VM job not yet green (DNS, mail/OpenDKIM, restore drill pending after fixes). RHEL support must not be claimed until it is. | Open |
| F-12 | MEDIUM | RHEL | "Restart PHP" used the Debian unit name (`php8.3-fpm.service`); on RHEL it is `php83-php-fpm.service`. | **Fixed**: the unit name comes from the agent's discovery |
| F-13 | HIGH | RHEL / SELinux | A server configuration restore moved files extracted in a staging folder into `/etc` with the staging folder's label, so Nginx could not read them (found by the AlmaLinux run). | **Fixed**: restored folders are relabelled (`restorecon`) |
| F-10 | MEDIUM | Doctor | No checks yet for Nginx, PHP-FPM, Redis, disk space, backup configuration. | **Fixed** + test |
| F-11 | MEDIUM | Performance | No measured limits. | **Fixed** (panel side): scale test in CI; limits in the table above |
| F-14 | HIGH | Multi-server | A server check recorded every reachable agent as `online`: the agent version was read from the wrong key (never stored), so version mismatches went unnoticed, and every failure — wrong token, certificate mismatch, timeout — was recorded as plain `offline`. | **Fixed**: `version_mismatch`, `auth_failed`, `certificate_mismatch`, `refused`, `timeout`; the doctor counts only `online` servers as healthy. Test added. |
| F-16 | **BLOCKER** | Backups (installed agent, Ubuntu) | On a real Ubuntu 24.04 install (agent under its systemd unit), a website backup fails: `fork/exec /usr/bin/tar: operation not permitted`. Anything the agent runs as a site account (backups, restores, cron "run now", git deploy hooks, app installers) is affected. Not seen by the real-host tests (they run the agent outside systemd) nor on AlmaLinux (same unit, backup and restore pass). Found by the new post-install test (F-07). | Open — diagnosing |
| F-17 | HIGH | Configuration writes (RHEL) | Rewriting a file WhaCP does not own with "ownership unchanged" (e.g. adding its include to `/etc/named.conf`) replaced it with a new `root:root` file. On RHEL `/etc/named.conf` is `root:named 0640`, so BIND could no longer read its own configuration (`rndc reconfig: permission denied`). | **Fixed**: the replacement takes the replaced file's owner and group. Test added. |
| F-18 | MEDIUM | Email (RHEL) | OpenDKIM reads its tables as root before dropping privileges; the DKIM folder was owned by the `opendkim` account, which SELinux does not let the DKIM domain bypass, so OpenDKIM refused to start. | **Fixed**: folder `root:opendkim 0750`. |
| F-15 | LOW | Tests | The file-manager adversarial test removed its folders while archive jobs it started were still writing (CI failure). | **Fixed**: the jobs manager gained `Drain()`, tests wait for their jobs. |
